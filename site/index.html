Vim for AI agents

neovain lets a coding agent edit a file with Vim's commands, a whole change per call. Every step applies, or none do.

Small edits: a tie

On a 70-line file with seven small edits, the two approaches tie: every run passed, and cost was the same. neovain halves the number of tool calls, but the Edit tool issues its calls in parallel, so both need about four model round trips. neovain agents also spend about a thousand extra thinking tokens working out line ranges, which makes them a few seconds slower. A 250 KB preloaded context, simulating a long session, doesn't change the picture.

What we learned

Reach for neovain when

  • A change moves, deletes or re-indents large blocks. The Edit tool retypes them; Vim's :m, :d and > don't.
  • The same change repeats across a file: :%s and :g do it in one step.
  • You want all-or-nothing edits. A failed step leaves the file untouched, and agents recover on the next call.

Stick with string replacement when

  • The change is small and local. Writing the new text directly is the reasoning; with Vim, the agent has to work out the keystrokes too.
  • The model is small. In an early pilot, Haiku needed about three times as long with neovain and failed one run in three.
  • Nobody will read the diff. Range arithmetic can go wrong and still be valid Vim; that is how the one failed large run happened.

Tool calls are not round trips. Current models send independent edits as parallel tool calls, so cutting the number of calls saves little. What does cost time and money is output: every token the model writes. neovain wins where it lets the agent say less.
